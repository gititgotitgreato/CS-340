While the definition of "computer scientist" may not be clear to many, it is self-explanatory: one with a professional interest in computers and their software who wishes to solve problems with them. The digital world of today is only possible because of them, with millions of computing related problems solved and many more in the future; thousands upon thousands needed to be solved for me to even be able to type this in GitHub. As a computer scientist myself, I have to have a process behind solving problems, such as the project detailed in this repo. Not much has really changed for any of the projects I've worked on at SNHU, so my process for this project was to break down every requirement into its own problem to be solved and to order them in an order that I think would make sense for the development process. For example, my first task, because I was working with a dashboard, was to get the Dash server to run, then somewhere in the middle was me implementing the map, and I saved cosmetic improvements for last, as functionality is much more important. I believe that, if I apply these principles to databases, any client I encounter will eventually be happy. Databases are just one of an uncountable  multitude of digital services invented by computer scientists, and a problem with multiple solutions that was realized was to find a better way to sort through and alter these databases. MongoDB is just one of those solutions, and with the PyMongo library, enabling Python programs to work with MongoDB databases and JSON elements, and the Dash framework, database-integrated programs became much easier to make. My program, a dashboard that allows the user to filter animals in a database and find out where they are on a map, its fundamental problems solved by these solutions, was made to address a problem experienced by Grazioso Salvare: how were they to find rescue animals from Texas animal shelters without taking a massive amount of time to decide by seeing them themselves? Since, with my program, they can now save countless hours by filtering out the right dogs for the job and finding their coordinates, which can easily be guided to with services like Google Maps, they can now spend more time researching training methods and improving the rescue animals they have now. However, Grazioso Salvare isn’t the only organization that can benefit from my program. This project is reusable and adaptable, so any organization that needs to find something or someone from a CSV database (ex. support for hurricane survivors based on need) can just change the cosmetic and text portions to what they need. The CRUD module made for this is a perfect example of why I like my code as reusable and maintainable as possible; it can be used across many different programs to create documents and read, update and delete them with simple Mongo queries. A focus on simplicity means that it does as little as it needs to, so it can be easily maintained and requires little change from program to program. This CRUD module, while not tested for such, may very well be simple enough to work for other kinds of databases, like SQL based databases, as long as the tests are tweaked to handle them and the limited JSON and MongoDB elements are updated to the required database format. Therefore, the biggest takeaway from this class for me is that, if it works or you think it will work, don’t overcomplicate things, because that will just make everything harder later on.
